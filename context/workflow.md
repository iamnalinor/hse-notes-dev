# Как добавить новый конспект: полный путь

Инструкция для агента, которому дали задачу «напиши конспект лекции N по курсу X», и для оркестратора, который раздаёт такие задачи. Все пути — от корня репозитория.

## 0. Окружение (один раз за сессию)

```bash
./scripts/setup.sh                     # TinyTeX + пакеты TeX Live + uv sync (идемпотентно, ~3 мин в первый раз)
export PATH="$HOME/.TinyTeX/bin/x86_64-linux:$PATH"
./scripts/fetch_sources.sh             # публичные репозитории-источники → sources/ (не коммитится)
uv run pytest -q                       # пайплайн жив
```

## 1. Найти лекцию в плане курса

Открой `context/courses/<course>.md` → «Расписание и план семестра».

- **Лекция есть в таблице.** Возьми `week_id`, дату, тему и `basis`, раздел «Лекции подробно» (если есть) и источники.
- **Лекции нет** (новая неделя, перенос):
  1. Дата: день лекции курса из `context/schedule.md`. Переносы и праздники сверь с Google Calendar «Education», если есть доступ. Перенос на другой день недели внеси в `templates/courses.json` → `date_exceptions`, иначе линтер не пропустит дату.
  2. Номер: следующий по порядку. Недели сессии не считаются.
  3. `week_id = {NN}_{mmmDD}_{slug}`: `NN` — номер с ведущим нулём, `mmmDD` — `sep03`, `oct23`…, slug — 1–3 английских слова через `_`. **Slug выбирается один раз и не меняется** — на него ссылается сайт.
  4. Добавь строку в таблицу плана со статусом «пишется».

## 2. Выбрать режим и собрать источники

| Режим | Когда | `basis` | `based_on` (пример) |
| --- | --- | --- | --- |
| По лекции | Лекция прошла, есть материалы именно этой лекции 2026: запись или субтитры, фото доски, тезисы лектора, конспект однокурсника | `lecture` | `лекция 23.09 (запись) + семинар 30.09` |
| Прогноз | Лекции ещё не было, или от неё нет материалов, кроме общего плана курса | `forecast` | `конспекты 2023/24 и план курса 2026/27 (черновик до лекции)` |

Только план или программа курса — это не материалы лекции: такой конспект остаётся прогнозом.

Источники перечислены в `context/sources.md` и разделе курса `context/courses/<course>.md`. Скачай нужное в `sources/<course>/…`: Google Drive — через Drive-коннектор, веб — через WebFetch, репозитории — `fetch_sources.sh`. Материалы этого года важнее прошлогодних: порядок тем, обозначения и объём берутся из 2026.

## 3. Прочитать перед тем, как писать (в этом порядке)

1. `context/conventions.md`: общая часть и раздел своего курса. Конспект пишется в обозначениях курса, а не учебника.
2. `context/recommendations.md` целиком: Р1–Р32, запреты, чеклист.
3. `context/markup.md`: синтаксис.
4. `context/prompts/generate.md`: шаги генерации.
5. Предыдущие конспекты курса `notes/<course>/*.md`, хотя бы последние два и все, на которые будешь ссылаться. Что уже определено, на то ссылайся и не повторяй.
6. Метки, которые уже есть: `uv run scripts/build.py --no-pdf --no-html`, затем смотри `build/index.json` → `labels.<course>`.

## 4. Написать

```bash
cp templates/note-skeleton.md notes/<course>/<week_id>.md
```

Дальше по `context/prompts/generate.md`. Все новые термины идут в глоссарий, каждый навык из «После прочтения ты сможешь» получает задачу в самопроверке.

## 5. Проверить машиной

```bash
uv run scripts/lint.py notes/<course>/<week_id>.md          # 0 ошибок; предупреждения разобрать
uv run scripts/build.py --only notes/<course>/<week_id>.md  # PDF + HTML без ошибок
```

Сборка падает на неизвестной ссылке, дубликате метки и ошибке LaTeX: сообщение указывает строку в `build/tex/<course>/<week_id>.tex` и лог. Предупреждение `overfull box` означает, что формула или строка вылезла за поле. Его нужно исправить: перенести формулу, разбить её через `aligned` или уменьшить рисунок.

## 6. Посмотреть глазами

```bash
uv run scripts/render_pages.py build/pdf/<course>/<week_id>.pdf --dpi 90
```

Открой PNG страниц (инструментом чтения изображений) и проверь рамки, колонтитул, формулы, рисунки и подписи, переносы. HTML-версия: `build/site-data/<course>/<week_id>/index.html` (KaTeX грузится с CDN). Скриншот можно снять Playwright: Chromium лежит в `/opt/pw-browsers/chromium`.

## 7. Чеклист, реестр, план

1. Пройди чеклист из конца `context/recommendations.md`. Невыполненный пункт означает переписать место, а не оговорку в конце.
2. Обнови `registry/<course>.md` по `context/prompts/registry.md`: добавь или замени раздел «Лекция N — тема».
3. В `context/courses/<course>.md` поставь статус «написан, ждёт ревью».

## 8. Ревью

Отдельный агент, не видевший генерации, проверяет конспект по `context/prompts/review.md`. Ему передают путь к `.md`, к PDF и к PNG страниц. Писатель исправляет замечания, ревью повторяется, пока есть замечания слоя 1 (математическая корректность); слой 1 — обязательное условие мерджа. Ответы на замечания и споры живут в отчёте или в PR, в конспект не попадают.

После ревью статус в плане курса: «готов (lecture)» или «готов (forecast)».

## 9. Коммит

```bash
git add notes/<course>/<week_id>.md registry/<course>.md context/courses/<course>.md
git commit -m "<course>: лекция N — <тема>"
```

PDF и `build/` не коммитятся: их собирает CI (`.github/workflows/build.yml`), PDF доступны как artifact и в релизе `latest`.

# Как перевести прогноз в конспект по лекции (нормировка)

Когда лекция с `basis: forecast` прошла и появились её материалы, работай по `context/prompts/normalize.md`. Коротко:

1. Сравни черновик с материалами: порядок тем, обозначения, объём, что лектор добавил или пропустил.
2. Исправь конспект и поставь `basis: lecture`, `based_on: лекция ДД.ММ (…)`. Метки существующих блоков сохрани. Удалённый блок — значит удалённая метка: проверь ссылки (`lint.py`).
3. Запиши расхождения прогноза с лекцией в `context/courses/<course>.md` → «Расхождения прогноза и лекций 2026». Это нужно для прогнозов следующего года.
4. Обнови реестр (снимется пометка «черновик»), затем ревью и коммит, как выше.
